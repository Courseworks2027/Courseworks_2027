Тема: TripPlanner — Платформа для совместного планирования путешествий

**TripPlanner** — это полноценное многопользовательское веб-приложение, которое решает главную боль групповых поездок: хаос в чатах. Платформа позволяет командам друзей или коллег совместно выбирать даты, направления, строить маршрут на карте и прозрачно вести общий бюджет без ручных расчетов в мессенджерах.

> 💡 *Проект разработан в рамках курсовой работы. Демонстрирует навыки проектирования реляционных баз данных, реализации сложной бизнес-логики, работы с внешними API и создания интерактивного SPA-интерфейса.*

---

##  Ключевой функционал (MVP)

Приложение разделено на 4 основных модуля:

### 1.  Управление поездками и участниками
* Создание события (поездки) с базовыми параметрами.
* Генерация уникальных пригласительных ссылок.
* Система ролей: **Организатор** (полный доступ, управление участниками) и **Участник** (голосование, добавление точек, учет расходов).

### 2.  Голосование за даты и места
* Пользователи могут предлагать несколько вариантов дат или городов.
* Механика «лайков» (голосов) за каждый вариант.
* **Автоматическое определение варианта-победителя** на основе агрегации голосов.

### 3.  Интерактивная карта маршрута
* Добавление точек интереса (POI): отели, музеи, кафе, достопримечательности.
* Привязка точек к конкретным дням поездки (таймлайн).
* Визуализация маркеров на карте и построение маршрутов между ними.

### 4.  Сплит-трекер бюджета
* Учет общих трат (кто, сколько и за что заплатил).
* **Алгоритм минимизации транзакций**: система автоматически рассчитывает, кто кому и сколько должен вернуть, сводя количество взаимных переводов к математическому минимуму.

##  Технологический стек

**Backend:**
* Язык: Python 3.10+
* Фреймворк: FastAPI *(или Django REST Framework)*
* Валидация: Pydantic *(или Django Serializers)*
* База данных: PostgreSQL *(или SQLite для старта)*, SQLAlchemy / Django ORM

**Frontend:**
* Базовые технологии: HTML5, CSS3, JavaScript (ES6+)
* Фреймворк/Подход: React *(или Vue.js / Jinja2 + HTMX)*
* HTTP-клиент: Fetch API / Axios

**Карты и Интеграции:**
* Карты: Leaflet.js + OpenStreetMap
* Документация API: Swagger (OpenAPI)

##  Команда и распределение ролей

Проект разработан командой из 3 человек. Зоны ответственности строго разделены для обеспечения параллельной разработки:

### Участник 1: Архитектор БД и бизнес-логики (Backend Core)
*Отвечает за фундамент приложения, структуру данных и сложные алгоритмы.*
* Проектирование и нормализация схемы реляционной БД (пользователи, поездки, точки, голоса, транзакции).
* Разработка и реализация **алгоритма взаиморасчетов** (минимизация графа долгов при закрытии бюджета).
* Написание логики агрегации данных (подсчет результатов голосований).
* Реализация системы проверки прав доступа (RBAC).
* Генерация итоговых артефактов (чек-листы, PDF-отчеты по поездке).

### Участник 2: Разработчик API и интеграций (Backend API)
*Отвечает за связку базы данных с клиентом и внешним миром.*
* Реализация системы авторизации и аутентификации (регистрация, вход, хеширование паролей, выдача JWT-токенов).
* Проектирование и написание REST API эндпоинтов (CRUD-операции для всех сущностей).
* Настройка строгой валидации входящих данных.
* Интеграция автоматической документации API (Swagger/OpenAPI).
* Обработка ошибок и стандартизация ответов сервера.

###  Участник 3: Frontend-разработчик и интегратор карт
*Отвечает за визуальную часть, UX/UI и работу с картографическими сервисами.*
* Верстка адаптивных страниц (дашборд поездки, список поездок, вкладка бюджета).
* Интеграция картографических библиотек (Leaflet/Яндекс): установка меток по клику, кастомизация иконок, отрисовка маршрутов.
* Настройка асинхронного взаимодействия с Backend (обновление голосов и расходов без перезагрузки страницы).
* Обеспечение кроссбраузерности и адаптивности интерфейса (Mobile First).
